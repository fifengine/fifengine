# Tier B: OpenGL 4.3 core / OpenGL ES 3.1 profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GL 4.3 core and ES 3.1 profiles to the Tier A `glcore/` backend family, plus an opt-in GPU particle path that keeps Track 1's semantics and CPU fallback intact.

**Architecture:** Tier B is two more `GLProfile` values, two more shader dialects, two new built-in programs, and a bridge object owned by the existing `RenderBackendGLCore`. The CPU keeps the particle pool, RNG, spawn scheduling, recycling and placement; the GPU only integrates live SSBO entries and draws instanced quads. `RenderBackend` gains one non-pure hook returning a GL-free `IParticleRenderBackend*`; `ParticleRenderer` falls back to `Image::render()` whenever that pointer is null or the emitter has not opted in.

**Tech Stack:** C++20, SDL3 context attributes, vendored glad (Tier A), GLSL 430 / ESSL 310 shaders with a compatibility macro layer, SSBOs + compute + instanced draws, CMake, Catch2.

**Spec:** `docs/superpowers/specs/2026-11-23-modern-gl-43-es31-design.md` — executors read both this plan and the spec. Prerequisites: `docs/superpowers/specs/2026-11-23-modern-gl-es2-design.md` (Tier A) and `docs/superpowers/specs/2026-11-23-particle-engine-design.md` (Track 1).

## Global Constraints

- **Tier A is already implemented and is NOT replanned here.** This tree does not yet contain `src/fife/video/glcore/`, `Track 1`'s `ParticleEmitter`/`ParticleManager`/`ParticleRenderer`, or the Tier A backend names. Plan and implement against the interfaces those specs define; do not re-create them, and do not branch the legacy `src/fife/video/opengl/` backend.
- Backend names are exactly `"OpenGL_43"` and `"GLES_31"`; listed in `EngineSettings::getPossibleRenderBackends()` only when their CMake options are compiled in, with the warned-SDL-fallback rule for stale config.
- CMake options are exactly `ENABLE_OPENGL_43` and `ENABLE_OPENGLES_31`; each requires `ENABLE_OPENGL=ON` **and** at least one Tier A option (`ENABLE_OPENGL_CORE` or `ENABLE_OPENGL_ES2`).
- New profiles are GLSL 430 (`#version 430 core`) and ESSL 310 (`#version 310 es`); Tier A keeps GLSL 330 and ESSL 100.
- Four-dialect shader matrix: GLSL 330, GLSL 430, ESSL 100, ESSL 310. The four existing programs compile in **all four** dialects; the two particle programs compile in **GLSL 430 / ESSL 310 only** (never GLSL 330 or ESSL 100).
- `maxParticles` is clamped to **2048** on the CPU path; with `computeEnabled` it may be set up to a hard bound of **262144**, further clamped by `GL_MAX_SHADER_STORAGE_BLOCK_SIZE` and available memory. **Drop-on-full applies on both paths.**
- CPU owns emission/recycling/RNG/placement (pool, free-index stack, seeded `std::mt19937`, emission accumulator, scheduled death times, `RendererNode`); GPU owns **only integration** (positions, velocities, colours, sizes, life) and instanced drawing. CPU never reads particle state back.
- `IParticleRenderBackend` is a GL-free abstract interface in `src/fife/video/`; `RenderBackend` exposes it through exactly `virtual IParticleRenderBackend* getParticleRenderBackend() { return nullptr; }` — non-pure, null default. Only the GLCore family overrides it; SDL, legacy OpenGL and both dummies keep the default.
- No bit-for-bit CPU/GPU equivalence: compare spawn counts, death scheduling, position ranges and centroid within documented tolerances only. Do not assert identical sequences.
- No GL 4.4+ features (direct state access 4.5 and SPIR-V 4.6 are out); no geometry or tessellation shaders.
- No indirect draw: `hasIndirectDraw()` is not part of this design; use plain instanced draws with CPU-supplied counts.
- No pure virtuals on `RenderBackend`.
- macOS / Windows-on-Arm are unsupported by this tier (GL 4.1 cap on macOS, 3.3 on Mesa D3D12 Win-on-Arm) and use Tier A or the legacy backend; this is a documented limitation, not a bug to fix here.
- C++20 and Catch2 (`all_tests`, with the `[dummy]` tag split into `all_tests_dummy`) throughout.
- Assumption naming: Tier A supplies `GLProfile`, `GLContextConfig`, `GLContext`, `ShaderLoader`, `ShaderCache`, `Buffer`, `VertexArray`, `RenderBackendGLCore`/`RenderBackendGLES2` under `src/fife/video/glcore/`, with macros `HAVE_OPENGL_CORE`/`HAVE_OPENGL_ES2`. Track 1 supplies `ParticleEmitter`, `ParticleManager`, `ParticleRenderer` with `setMaxParticles(uint32_t)`, `getMaxParticles() const`, `getCapacity() const`, `getAliveCount() const`, `setSeed(uint32_t)` and `getParticle(size_t)`. Tier B's Task 4 extends the cap logic when `computeEnabled` is set; the 2048 clamp is the CPU-path default inherited from Track 1. Match the actual landed names if they differ; keep the signatures below as the contract between tasks.

## Review Focus

- CPU path silently doing GPU work (emission/recycling/RNG/placement reimplemented in GLSL, or semantics drifting when `computeEnabled` is on) — expect identical spawn/death scheduling and a 1:1 upload-per-spawn — pinned by `test_gpu_particles.cpp` in Task 4.
- Cap divergence: 2048 clamp lost on CPU path, or GPU cap exceeding 262144 / ignoring the SSBO-size bound / dropping overflow incorrectly — pinned by `test_gpu_particles.cpp` in Task 4.
- Shader dialect matrix breaks: particle programs compiled for GLSL 330 / ESSL 100, or the compat macros break ESSL 310 precision — pinned by `test_modern_gl_shader_dialects.cpp` in Task 2.
- SSBO invalidation missed or over-eager: changing rates/colours/lifetimes/seed must not reallocate; emitter removal, `maxParticles`, `computeEnabled` and context recreation must — pinned by `test_gpu_particles.cpp` in Task 4.
- Capability interface leaks GL types into `video/` or stops being a null default on non-GLCore backends — pinned by `test_particle_backend_header.cpp` and `test_modern_gl_backend_names.cpp` in Tasks 4 and 3.
